# Preserve existing APK signatures while injecting channel metadata

Channel packaging changes only the VasDolly channel metadata: a V1 ZIP comment marker or a V2/V3 Signing Block ID-value pair. Existing APK content and V2/V3 signature payloads are preserved, so packaging does not require private signing keys or a second signing pass.

## Considered Options

- Re-sign every generated channel package.
- Store channel metadata inside signed ZIP entries.
- Preserve the signed APK and inject only the VasDolly metadata location.

## Consequences

Generated channel packages retain the base APK's signature validity and can be produced from a signed APK without access to its signing key. V4 sidecar signatures are not regenerated by this operation.

*(Note: Extended by [ADR-0005](0005-support-walle-and-custom-signing-block-ids.md) to support Walle JSON payloads and custom Signing Block IDs in addition to standard VasDolly metadata.)*
